# Pinned six-moon reconstruction inputs

These gzip files contain lossless little-endian float64 `ElementRow` values
parsed from original NASA/JPL Horizons responses. The manifest names each field,
records both normalized-byte and original-response hashes, and retains verified
provider headers, exact cache-key-checked requests, and source provenance.
They are numerical source records, not values reconstructed from fitted models.

Regenerate or verify the separate extension on Linux x86-64 with glibc 2.39,
Python 3.12.13, NumPy 2.5.2 and the complete pinned
`ci/backend-test-requirements.txt` environment. Select the NumPy wheel's OpenBLAS
0.3.34 Nehalem kernel and one thread before Python starts:

```sh
export PYTHONHASHSEED=0 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1 TZ=UTC
export OPENBLAS_CORETYPE=Nehalem
uv run --python 3.12.13 --with-requirements ci/backend-test-requirements.txt \
  python scripts/ci/catalog_numerical_profile.py --require-core Nehalem
uv run --python 3.12.13 --with-requirements ci/backend-test-requirements.txt \
  python scripts/generate_moon_repairs.py --offline --write
uv run --python 3.12.13 --with-requirements ci/backend-test-requirements.txt \
  python scripts/generate_moon_repairs.py --offline --check
uv run --python 3.12.13 --with-requirements ci/backend-test-requirements.txt \
  python -m pytest -q scripts/test_moon_repairs.py
```

The shared reconstruction uses scalar `math.atan2` for both node and periapsis
angles, avoiding the observed NumPy `arctan2` CPU-dispatch rounding difference.
The fixed BLAS kernel prevents the observed least-squares differences between
CPU kernels. CI verifies the actual Nehalem kernel and one thread, then requires
exact extension bytes with native NumPy dispatch and with
`NPY_DISABLE_CPU_FEATURES=X86_V4`, both using that BLAS kernel. This contract
covers the pinned stack; other platforms, native library builds and libm
implementations require separate verification.

Regeneration refreshes the extension's generated bytes and the lazy index's
base-artifact hash using these same immutable source records. Source hashes,
retained timestamps and their provenance qualifications remain historical.
Strict byte equality and the original numerical acceptance gates are retained.

The canonical four-body file is a separate artifact owned by
`generate_moon_ephemeris.py`. Its bytes and complete-file reproducibility check
are preserved. The six-moon generator validates every held-out grid state,
coverage endpoints and seven independent vector epochs against the original
accuracy limits. These sampled gates are not continuous uncertainty bounds.

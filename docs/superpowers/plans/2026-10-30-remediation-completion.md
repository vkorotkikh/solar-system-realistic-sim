# Remediation completion and note retirement

Goal: finish every requirement represented by the remediation notes, verify the
combined application, and delete a note only when all of its requirements close.
The October 29 consolidated review and its 83-entry register are the input spec.

## Invariants

- Preserve scientific thresholds, complete catalog identities, original fitted
  moon hashes, native provenance, honest fallback, and explicit skipped coverage.
- User main and existing worktrees remain untouched; integration is isolated on
  `fix/remediation-completion-20261030`.
- Keep the existing 30-sample risk floor while adding departure/delivery mass
  separation; the source branch's unrelated constant refactor is not required.
- Startup composition has one owner. UI changes supply a main.ts handoff.
- Preserve proof in Git and the consolidated record before deleting any note.
- External permissions, deployed TLS/auth, actual assistive-device evidence and
  unsupported platform contracts require their real evidence or owner decision.

## Dependencies and rulings

- Cargo risk and storage fixes share the mass ledger: departure cargo drives
  rocket closure, surviving arrival cargo drives realized-yield reporting.
- Startup/UI share composition: startup alone edits main.ts; browser owner sends
  exact integration requirements for panel width and immediate camera feedback.
- Solar native inputs may affect pinned scientific inputs: refresh only hashes of
  intentionally changed production inputs after source freezes; never tolerances.
- All-424 publication and distribution acceptance remain distinct from local
  candidate numerical acceptance; no renderer activation is implied.

## Completion rule

For each note retain its original SHA, covered IDs and named children, final
source revision, exact verification evidence and remaining blockers. An open
child, unknown deployment or absent manual/permission proof prevents deletion.

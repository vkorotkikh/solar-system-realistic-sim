## Scope
- Re-analysis of Earth/Mars satellite handling architecture and scalability path.
- Validation pass on Mars moon orbit/rotation modeling data path.
- Immediate UX/visual fixes: adaptive near-surface zoom for Earth/Moon/Mars and non-uniform textures for minor moons.

## Current state (code audit)
- Satellite/orbiter propagation is implemented in `OrbitalSatelliteSystem` as two-body Kepler with optional J2 secular precession:
  - `src/frontend/features/planetary/satelliteSystem.js`
  - Core propagation: `propagateAroundPrimary(...)`
  - Earth default ingest: TLE sources (CelesTrak stations + GEO)
  - Moon/Mars default ingest: profile catalog fallback
- Rendering model is one `Mesh` per satellite marker + one `Line` per orbit track.
- Systems are planet-scoped and attach to body nodes (`earth`, `moon`, `mars`), with scale-mode awareness.

## Gaps versus high-fidelity / high-scale architecture
1. Per-object draw-call model does not scale to 10k+ objects.
2. Propagation executes on main thread and updates every frame for every object.
3. TLE/mean-element path is Earth-centric; no generalized SPICE ephemeris path for multi-planet satellites.
4. Orbit line rendering is O(N) geometry-heavy and should become LOD/event-gated.
5. Frame transformations were previously approximate for non-ecliptic moon element frames.

## Mars moon validation findings
- Data source is JPL SSD natural satellites table (`scripts/update-moons-data.mjs` pulls from `https://ssd.jpl.nasa.gov/sats/elem/`).
- Local Mars moon source entries remain:
  - Phobos: a=9375 km, e=0.015, i=1.1 deg, frame=Laplace, period=0.3187 d
  - Deimos: a=23457 km, e=0.0, i=1.8 deg, frame=Laplace, period=1.2625 d
- Previous frame conversion logic underused source-pole orientation and could under-tilt Laplace-frame orbits in ecliptic rendering.

## Roadmap for 10k+ and multi-planet deployment
### Phase 1: Data-model and API split
1. Define `EphemerisProvider` interface (TLE/OMM provider, SPICE provider, catalog/analytic provider).
2. Define `Propagator` interface (SGP4, DSST/semi-analytic, numerical Cowell).
3. Introduce canonical state vector schema (position/velocity in inertial frame + covariance optional).

### Phase 2: Compute scalability
1. Move propagation into worker threads (batched by primary body).
2. Add variable-rate updates by altitude/importance (near-camera high rate, far-field low rate).
3. Add propagation cache and interpolation (Hermite/cubic between keyframes).

### Phase 3: Rendering scalability
1. Replace per-satellite meshes with `InstancedMesh` markers per primary/category.
2. Add LOD orbit rendering:
   - near-camera: sampled track
   - mid/far: analytic ring/arc proxy
   - deep far: disabled
3. Add GPU frustum/distance culling prepass for marker instances.

### Phase 4: Accuracy upgrades
1. Earth: SGP4/SDP4 ingest from OMM/TLE with epoch quality checks.
2. Planetary systems: SPICE SPK kernels as preferred truth source.
3. Optional higher fidelity force models for selected objects: J2/J4, SRP, third-body, drag (Earth only).

### Phase 5: Operations and maintainability
1. Add golden-orbit regression tests (ISS, GEO exemplar, Phobos/Deimos) with tolerance budgets.
2. Add deterministic replay mode (fixed step + seeded perturbations).
3. Add telemetry dashboards for propagation error/time budget per frame.

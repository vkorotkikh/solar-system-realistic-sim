## Scope Covered

This report captures the current conclusions from the backend evaluation pass, compares the project to current high-fidelity simulation ecosystems (as of February 15, 2026), identifies missing capability layers, and proposes a concrete step-by-step implementation plan with an agentic AI architecture direction.

## Current Backend Findings (Code-Grounded)

1. N-body propagation core is strong for interactive use.
- REBOUND engine supports IAS15, WHFast, and Mercurius.
- Measured locally: IAS15 has very low energy drift; WHFast/Mercurius provide major speedups.

2. Trajectory planner is deterministic but heuristic-level.
- Current route scoring is patched-conic/Hohmann-style with soft-scored gravity assists.
- It is not yet a Lambert solver or constrained optimizer.

3. Feasibility handling is currently penalty-based.
- Assist turn-limit infeasibility is penalized, not hard-rejected.
- This can allow physically questionable routes to rank high for some objectives.

4. Body catalog used by backend is limited for mission planning depth.
- Backend includes 41 bodies (planets, dwarfs, asteroids) and excludes moons from planning route options.
- Several bodies have missing mass, reducing force-model and assist realism.

5. Validation and mission-grade analysis layers are not yet present.
- No trajectory verification harness against SPICE/HORIZONS truth outputs.
- No uncertainty propagation, covariance, or Monte Carlo envelope reporting.

6. Notable integration risk to patch soon.
- Simulation runner emits energy error each frame; engine interface consistency for that metric should be standardized across engines.

## Comparison vs Current High-Fidelity State of the Art (Feb 15, 2026)

| Capability | Current backend | Established high-fidelity simulators |
|---|---|---|
| N-body dynamics | Good REBOUND core for multi-body gravity | REBOUND remains top-tier for N-body; GMAT/Orekit/Tudat/Basilisk add broader mission toolchains |
| Force models | Mostly point-mass in active path; optional Tudat path | Mature stacks include richer perturbation modeling (SRP, harmonics, atmosphere/drag, detailed force model controls) |
| Trajectory solving | Heuristic patched-conic route scorer | Lambert, targeting, boundary-value solving, and optimization pipelines |
| Maneuver realism | No finite-burn or low-thrust vehicle dynamics stack | Mature mission tools support impulsive, finite-burn, and low-thrust modeling |
| Estimation / navigation | Not present | Orekit/Tudat/GMAT-class workflows include OD/estimation capabilities |
| Mission ops / FSW loop | Not present | Basilisk and MONTE-class ecosystems support deeper mission operations loops |

## What Is Missing for High-Fidelity Mission Simulation

- Hard-constrained trajectory design (Lambert legs, launch window scanning, MGA search).
- Spacecraft state and propulsion model (dry mass, propellant, thrust, Isp, staging, margins).
- Burn modeling layers (impulsive, finite-burn, low-thrust).
- Uncertainty and risk stack (covariance, Monte Carlo, sensitivity surfaces).
- Closed-loop mission timeline logic (depart, rendezvous, mine, return, abort).
- Mining/ISRU model (ore grade, extraction throughput, refining yield, storage and transfer losses).
- Truth-comparison and regression harness (SPICE/HORIZONS cross-checks).

## Improved Step-by-Step Implementation Plan

1. Stabilize core interfaces and validation baseline.
- Standardize simulation engine telemetry contract across REBOUND and Tudat paths.
- Add regression tests for planner determinism and simulation-state schema.
- Deliverable: reliable backend contracts and CI checks before feature expansion.

2. Add an ephemeris truth service.
- Implement `ephemeris_service` with SPICE/HORIZONS-aligned body state sampling.
- Keep current element-based states as fallback mode.
- Deliverable: authoritative state source for route verification.

3. Replace heuristic transfer core with Lambert plus window search.
- Implement Lambert solver endpoint and porkchop grid scan.
- Produce Pareto outputs (time-of-flight vs total delta-v).
- Keep gravity-assist search but switch scoring to physically constrained legs.
- Deliverable: mission-grade travel-time and transfer feasibility outputs.

4. Add multi-gravity-assist (MGA) optimization layer.
- Support sequence search with hard feasibility constraints.
- Enforce flyby geometry limits as hard constraints, not soft penalties.
- Deliverable: realistic multi-leg interplanetary route synthesis.

5. Introduce vehicle and maneuver modeling.
- Add `vehicle_service` with rocket equation, stage definitions, and finite-burn approximations.
- Attach maneuver budgets directly to route legs.
- Deliverable: payload-aware route feasibility, not just geometric transfers.

6. Add asteroid mining and return logistics model.
- Add `mining_service` with ore grade assumptions, extraction/refining throughput, and power constraints.
- Add transport return closure model: mined mass -> processed payload -> returnable payload after propellant.
- Deliverable: computed payload returned to destination for mission start conditions.

7. Add uncertainty, risk, and operations constraints.
- Add `risk_service` Monte Carlo sweeps over ephemeris, thrust, and extraction-rate uncertainty.
- Track confidence intervals for arrival date, fuel margin, and returned payload.
- Deliverable: probabilistic mission outcomes instead of single-point estimates.

8. Add agentic orchestration on top of deterministic services.
- `MissionPlannerAgent`: decomposes mission into outbound, rendezvous, mining, and return phases.
- `TrajectoryAgent`: proposes and refines route candidates using solver endpoints.
- `MiningAgent`: computes extraction profile and payload timeline.
- `LogisticsAgent`: enforces mass, fuel, timing, and vehicle constraints.
- `VerifierAgent`: validates physical consistency and rejects infeasible plans.
- Deliverable: explainable multi-agent planning workflow with deterministic tool calls.

9. Add explainability and decision logs.
- For each recommended plan, emit “why this plan won” metrics.
- Persist trade studies and rejected alternatives for reproducibility.
- Deliverable: auditable mission decision pipeline.

10. Benchmark against reference tools and publish accuracy report.
- Compare selected scenarios against GMAT/Orekit/Tudat reference outputs.
- Report timing, delta-v deltas, arrival errors, and sensitivity behavior.
- Deliverable: confidence-backed fidelity statement for users and contributors.

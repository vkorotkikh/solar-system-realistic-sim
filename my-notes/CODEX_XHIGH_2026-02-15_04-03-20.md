## Additional pass: Saturn/Uranus ring-axis issue analysis
### Findings
- Ring meshes were attached to `spinGroup` (correct), but spin-axis direction was defined only by obliquity and forced into a fixed +X azimuth in ecliptic coordinates.
- This means ring-plane tilt direction lacked per-planet pole longitude, which made ring orientation appear wrong for Saturn/Uranus depending orbital phase and camera frame.
- Ring and guide-ring meshes were also participating in generic `updateBodyRotations`, which is not desirable for static ring-plane visualization.

### Conclusion
- The main issue was missing spin-axis azimuth (pole longitude), not ring geometry radius.
- Secondary cleanup: ring meshes should be excluded from body-spin animation updates.

### Code modifications
- Added `spinAxisLongitudeDeg` to ringed planets in planetary constants:
  - Saturn: `79.53 deg`
  - Uranus: `257.65 deg`
- Updated spin-axis construction in `createBodyNode` to use both obliquity and azimuth.
- Added `lockBodySpin` flag for ring meshes and orbit-guide rings.
- Updated `updateBodyRotations` to skip children marked with `lockBodySpin`.

### Verification
- `npm run build` succeeded after ring-axis fix changes.

## Bugfix pass: startup giant Earth/Mars blobs in non-realistic mode (2026-02-16 01:08 EST)
### Symptom observed
- On initial app launch in non-realistic scale mode, Earth and Mars showed giant faceted yellow/orange spheres centered on each planet.
- Toggling realistic scale on and off removed them for the rest of the session.

### Root cause
- Satellite marker meshes are created with `SphereGeometry(1, 10, 8)` in `OrbitalSatelliteSystem.buildSceneObjects()`.
- The system was calling `applyScaleMode()` before async satellite initialization, but meshes are created during `initialize()` after that call.
- New marker meshes therefore kept default scale `1.0` on first load (massive in AU scene units), producing the giant blobs.
- Later toggling realistic mode re-ran `applyScaleMode()`, shrinking those markers to expected AU marker sizes, which is why blobs disappeared.

### Code modifications
- `src/frontend/features/planetary/satelliteSystem.js`
  - Added persistent `currentMarkerScaleAu` state in constructor.
  - Applied marker scale immediately when each marker mesh is created in `buildSceneObjects()`.
  - Updated `applyScaleMode()` to refresh `currentMarkerScaleAu` and reapply it to all existing marker meshes.
- `src/main.js`
  - Added a defensive `system.applyScaleMode(simState.useRealisticScale)` immediately after each satellite layer `initialize()` call in `initializeEarthSatelliteLayer()`.

### Verification
- `npm run build` completed successfully after changes.
- Startup ordering now guarantees marker meshes are scaled correctly even before any user toggle interactions.

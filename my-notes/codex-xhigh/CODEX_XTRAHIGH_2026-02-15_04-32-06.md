# CODEX XTRAHIGH Deep Audit - Solar System Realistic Sim

## Deep Pass Summary
Deep pass complete. I reviewed backend + frontend code paths, ran runtime probes, and validated with `pytest -q` and `npm run build`.

- `pytest -q`: 8 passed
- `npm run build`: succeeds, but warns about a large JS chunk (`index-*.js` ~972 kB minified)

## Findings (Ordered by Severity)

### CRITICAL
1. `/mission/plan` can throw unhandled exceptions (500) on malformed payload fields.
- `backend/server.py:387` calls planner directly.
- Raw `float/int` casts at `backend/mission/agents.py:224`, `backend/mission/agents.py:226`, `backend/mission/agents.py:229`, and `backend/mission/agents.py:16`.
- Confirmed at runtime: bad `max_assists` or bad `vehicle.stages[*].dry_mass_kg` raises `ValueError`.

2. Mission planner can return `status: "ok"` with an invalid recommendation.
- Verification computed at `backend/mission/agents.py:393`.
- Sorted at `backend/mission/agents.py:411`.
- Always returns top candidate with `status: "ok"` at `backend/mission/agents.py:419`.
- Confirmed at runtime: `status=ok` with `verification.valid=False`.

3. Mission planner ignores UI `prograde` toggle.
- UI sends `prograde` in mission request: `src/frontend/features/trajectory/index.js:183`.
- Mission path never propagates `prograde` to trajectory solver: `backend/mission/agents.py:55`.
- Solver defaults to prograde when omitted: `backend/trajectory/planner.py:27`.
- Runtime check showed identical mission result for `prograde=True` vs `False`.

4. Arbitrary file write path in benchmark report API.
- User-controlled path accepted at `backend/server.py:413`.
- Path written directly at `backend/benchmark/accuracy.py:158`.
- Also unhandled type errors (500) for invalid `output_path` types.

### HIGH
5. `/trajectory/porkchop` has no effective workload cap.
- Input validation checks positivity only: `backend/server.py:327`, `backend/server.py:345`.
- Nested scan loops at `backend/trajectory/lambert.py:281`, `backend/trajectory/lambert.py:283`.
- Full `points`/`failures` accumulated in memory before truncation at `backend/trajectory/lambert.py:277`, `backend/trajectory/lambert.py:278`.

6. WebSocket client hardcoded to `ws://localhost`, breaking remote/HTTPS deployments.
- `src/main.js:2922`.

7. Backend mode time controls are not synchronized.
- Pause toggle mutates local state only: `src/main.js:4181`.
- "Now" button mutates local JD only: `src/main.js:4186`.
- Only `set_time_scale` continuously sent: `src/main.js:4414`.
- Only initial connect may send pause: `src/main.js:2939`.

8. Command spam risk: `set_time_scale` sent every frame.
- `src/main.js:4414`.
- Backend already has overflow/backpressure behavior: `backend/server.py:456`, `backend/server.py:527`.

9. CORS config is unsafe/inconsistent for credentialed cross-origin use.
- `allow_origins=["*"]` with `allow_credentials=True`: `backend/server.py:75`, `backend/server.py:76`.

### MEDIUM
10. Route visualization leaks GPU resources.
- `routeGroup.clear()` without disposal: `src/main.js:3828`, `src/main.js:3835`.
- New `BufferGeometry`/`LineBasicMaterial` created each plot: `src/main.js:3848`, `src/main.js:3851`.

11. Cloud bitmap cache eviction can leak memory.
- Bitmaps created at `src/frontend/features/planetary/cloudDataPipeline.js:180`.
- Eviction deletes map entry but does not call `bitmap.close()`: `src/frontend/features/planetary/cloudDataPipeline.js:189`.

12. Avoidable per-frame allocation/CPU churn in animation paths.
- New `Vector3` per satellite update frame: `src/frontend/features/planetary/satelliteSystem.js:573`.
- Route curve rebuild allocates vectors every frame via `buildTransferCurvePoints`: `src/main.js:3894`, `src/frontend/features/trajectory/localPlanner.js:255`.
- Recomputes bounding spheres per frame: `src/main.js:3902`.

13. Backend route failure is silently masked by local fallback.
- Catch-all fallback in planner call: `src/frontend/features/trajectory/index.js:209`, `src/frontend/features/trajectory/index.js:212`.
- Can hide backend regressions and mix physics models unexpectedly.

14. Testing gaps around API contracts and negative paths.
- Backend tests mostly service-level happy path: `backend/tests/test_mission_agents.py:7`, `backend/tests/test_trajectory_regression.py:44`.
- No FastAPI endpoint contract/error tests.

15. Frontend quality gates are missing.
- No `test`/`lint` scripts in `package.json:6`.
- Build-only pipeline increases regression risk (`src/main.js` is ~4483 lines).

### LOW
16. Production bundle is heavy.
- Build warning shows large main chunk (~972 kB minified), increasing startup/parse cost.

## Conclusions
- Physics/planning core is functional (tests pass), but API hardening and contract correctness are the biggest risk.
- Mission planning path has correctness bugs (`status: ok` invalid outputs, ignored `prograde`).
- Frontend/backend simulation coupling has deployability and control-sync issues.
- Memory/performance cleanup is needed for long interactive sessions.

## Priority Fix Plan
1. Add strict request schemas (Pydantic models) for `/mission/plan`, `/trajectory/porkchop`, `/benchmark/accuracy/report`; return 4xx on bad input (no raw 500 on user payloads).
2. Fix mission contract: propagate `prograde` through mission trajectory calls; if no verified candidate exists, return non-`ok` status with `recommendation: null`.
3. Lock benchmark report writes to a safe base directory (`my-notes/`), reject absolute/parent traversal paths, validate `output_path` type.
4. Add hard caps for porkchop grid size and total evaluated points; reject oversized requests.
5. Build WebSocket URL from `window.location` + protocol (`ws`/`wss`) instead of hardcoded localhost.
6. Send simulation control commands only on change and on relevant UI actions (`pause`/`resume`/`set_julian_date`).
7. Dispose old geometries/materials when clearing/replotting routes; close evicted image bitmaps.
8. Add backend API tests for invalid payloads and mission validity semantics.
9. Add frontend lint/test scripts and smoke tests for planner/sim-control flows.
10. Split `src/main.js` into feature modules and code-split planner/mission UI.

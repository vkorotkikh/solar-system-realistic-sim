## Priority Fix Plan (Execution Order)

| Priority | Change | Why First |
|---|---|---|
| P0 | Add porkchop hard caps (`max_grid_points`, max spans, compute budget rejection) | Removes highest-risk compute amplifier and protects API stability. |
| P0 | Replace wildcard CORS with env-configured allowlist and credentials policy | Required for safe, standards-compliant browser deployment. |
| P1 | Sync backend JD on `Now` and date actions via `set_julian_date` | Fixes user-visible correctness gap in backend mode. |
| P1 | Send `set_time_scale` only on change (not per-frame) | Reduces command spam and queue pressure. |
| P1 | Make planner fallback policy explicit (`strict backend` vs `allow local fallback`) | Prevents silent model switching and hidden regressions. |
| P2 | Surface backend planner error details in UI | Improves debuggability and user trust. |
| P2 | Route renderer perf pass (preallocated buffers, avoid per-frame clones/curve object churn) | Lowers frame-time jitter and GC churn. |
| P2 | Align mission unknown-body semantics with trajectory endpoints | Improves API consistency and client handling. |
| P3 | Add frontend lint + test scripts (unit + smoke e2e) | Introduces quality gates commensurate with app size. |
| P3 | Consolidate mission validation path (single source of truth) | Removes drift risk between API schema and internal parser. |

## Bottom Line

The codebase is materially healthier than three days ago on mission safety and API hardening, but not yet platform-hardened for hostile/untrusted workloads or production-grade backend-control UX. The immediate technical trajectory should prioritize: **porkchop caps, CORS correction, and backend time-sync correctness** before further feature accretion.
